# Agent 核心设计

## Agent 架构

```
┌─────────────────────────────────────────────────────────────┐
│                        AI Agent                              │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐ │
│  │                    Agent Loop                           │ │
│  │                                                         │ │
│  │   ┌─────────┐    ┌─────────┐    ┌─────────┐           │ │
│  │   │  Plan   │───►│ Execute │───►│ Observe │──┐        │ │
│  │   │  规划   │    │  执行   │    │  观察   │  │        │ │
│  │   └─────────┘    └─────────┘    └─────────┘  │        │ │
│  │        ▲                                      │        │ │
│  │        └──────────────────────────────────────┘        │ │
│  │                    (循环直到任务完成)                    │ │
│  └────────────────────────────────────────────────────────┘ │
│                              │                               │
│                              ▼                               │
│  ┌────────────────────────────────────────────────────────┐ │
│  │                   组件层                                 │ │
│  │                                                         │ │

│  │  │ 大脑/推理 │  │ 手/执行  │  │ 记忆/上下文│             │ │

│  │                                                         │ │
│  └────────────────────────────────────────────────────────┘ │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## 核心组件

### 1. LLM (大脑)

负责理解、推理、决策。

```
职责：
├── 理解用户意图
├── 分析当前情况
├── 决定调用哪个工具
├── 分析工具返回结果
└── 生成最终回复
```

### 2. Tools (手)

Agent 与外部世界交互的能力。

```
职责：
├── 执行具体操作 (SSH 命令、API 调用)
├── 获取信息 (日志、指标、状态)
└── 修改状态 (重启服务、清理文件)
```

### 3. Memory (记忆)

维护上下文和状态。

```
职责：
├── 短期记忆：当前对话历史
├── 工作记忆：当前任务状态、中间结果
└── 长期记忆：历史经验、知识库 (可选)
```

## Agent Loop 详解

### 单轮交互流程

```
用户: "查看 node-10 的 nginx 日志"
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ Step 1: 构造 Prompt                                      │
│                                                         │
│ System Prompt:                                          │
│ """                                                     │
│ 你是一个运维助手 Agent。                                  │
│                                                         │
│ 你有以下工具可用：                                        │
│ 1. query_log: 查询指定节点的日志                          │
│    参数: host(节点名), log_type(日志类型), lines(行数)     │
│                                                         │
│ 2. check_disk: 检查磁盘使用率                             │
│    参数: host(节点名，可选)                               │
│ ...                                                     │
│                                                         │
│ 当你需要执行操作时，返回 JSON 格式：                       │
│ {"tool": "工具名", "params": {...}}                      │
│                                                         │
│ 当你可以直接回答时，返回普通文本。                         │
│ """                                                     │
│                                                         │
│ User: 查看 node-10 的 nginx 日志                         │
└─────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ Step 2: LLM 推理                                         │
│                                                         │
│ LLM 思考：                                               │
│ - 用户想看日志                                           │
│ - 目标节点是 node-10                                     │
│ - 日志类型是 nginx                                       │
│ - 没说行数，用默认值                                      │
│ - 我需要调用 query_log 工具                              │
│                                                         │
│ LLM 输出：                                               │
│ {"tool": "query_log", "params": {"host": "node-10",     │
│  "log_type": "nginx", "lines": 100}}                    │
└─────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ Step 3: 解析 & 执行                                      │
│                                                         │
│ Agent 解析 LLM 输出，识别出工具调用                       │
│ 调用 query_log Tool                                     │
│ Tool 内部: SSH 到 node-10 执行 tail -100 /var/log/nginx/error.log │
│ 返回日志内容                                             │
└─────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ Step 4: 结果返回 LLM                                     │
│                                                         │
│ 将工具执行结果追加到对话：                                 │
│                                                         │
│ Assistant: {"tool": "query_log", ...}                   │
│ Tool Result: [日志内容...]                               │
│                                                         │
│ 再次调用 LLM，让它分析结果并生成回复                       │
└─────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ Step 5: 生成最终回复                                     │
│                                                         │
│ LLM 分析日志内容，生成自然语言总结：                       │
│                                                         │
│ "node-10 的 nginx 日志显示：                             │
│  - 最近 1 小时有 3 次 502 错误                           │
│  - 主要发生在 /api/users 接口                            │
│  - 可能是后端服务响应超时导致                             │
│  需要我进一步检查后端服务状态吗？"                         │
└─────────────────────────────────────────────────────────┘
```

```
用户: "帮我排查 node-10 为什么响应慢"
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ 第一轮: LLM 规划                                         │
│                                                         │
│ LLM 思考：排查响应慢需要检查多个方面                       │
│ 决定先检查 CPU                                           │
│                                                         │
│ 输出: {"tool": "check_cpu", "params": {"host": "node-10"}} │
└─────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ 执行 check_cpu → 返回: CPU 使用率 30%，正常               │
└─────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ 第二轮: LLM 继续                                         │
│                                                         │
│ LLM 思考：CPU 正常，继续检查内存                          │
│                                                         │
│ 输出: {"tool": "check_memory", "params": {"host": "node-10"}} │
└─────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ 执行 check_memory → 返回: 内存使用率 95%，很高！          │
└─────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ 第三轮: LLM 深入                                         │
│                                                         │
│ LLM 思考：内存很高，需要看看是哪个进程占用                 │
│                                                         │
│ 输出: {"tool": "run_command", "params":                 │
│        {"host": "node-10", "command": "ps aux --sort=-%mem | head -10"}} │
└─────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ 执行命令 → 返回: java 进程占用 80% 内存                   │
└─────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────┐
│ 第四轮: LLM 总结                                         │
│                                                         │
│ LLM 判断：已经找到原因，可以总结了                        │
│                                                         │
│ 输出 (自然语言):                                         │
│ "排查结果：                                              │
│  1. CPU 使用率 30%，正常                                 │
│  2. 内存使用率 95%，异常偏高                              │
│  3. 主要是 java 进程 (PID: 12345) 占用了 80% 内存         │
│                                                         │
│  建议：                                                  │
│  - 检查 Java 应用是否有内存泄漏                           │
│  - 考虑增加 JVM 堆内存限制或重启服务                       │
│                                                         │
│  需要我帮你重启这个 Java 服务吗？"                        │
└─────────────────────────────────────────────────────────┘
```

## ReAct 模式

我们采用 ReAct (Reasoning + Acting) 模式：

```
┌─────────────────────────────────────────────────────────┐
│                     ReAct 模式                          │
│                                                         │
│  Thought: 我需要先检查 CPU 使用情况                      │
│  Action:  {"tool": "check_cpu", "params": {...}}        │
│  Observation: CPU 30%，正常                             │
│                                                         │
│  Thought: CPU 正常，继续检查内存                         │
│  Action:  {"tool": "check_memory", "params": {...}}     │
│  Observation: 内存 95%，很高                            │
│                                                         │
│  Thought: 内存高，需要找出占用高的进程                    │
│  Action:  {"tool": "run_command", "params": {...}}      │
│  Observation: java 进程占用 80%                         │
│                                                         │
│  Thought: 找到原因了，可以总结                           │
│  Final Answer: 排查结果是...                            │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 关键设计决策

### 1. 工具调用格式

使用 JSON 格式，便于解析：

```json
{
  "thought": "用户想查看日志，我需要调用 query_log",
  "tool": "query_log",
  "params": {
    "host": "node-10",
    "log_type": "nginx",
    "lines": 100
  }
}
```

### 2. 循环终止条件

```
Agent 循环在以下情况终止：
├── LLM 返回普通文本（非工具调用）→ 任务完成
├── 达到最大循环次数 → 防止无限循环
├── 工具执行出错且无法恢复 → 报错退出
└── 用户中断 → 停止执行
```

### 3. 错误处理

```
工具执行失败时：
├── 将错误信息返回给 LLM
├── LLM 决定：重试 / 换方法 / 报告用户
└── 不是简单地抛出异常
```

### 4. 上下文管理

```
对话历史管理：
├── 保留完整对话历史（用户消息 + Agent 回复 + 工具结果）
├── 超长时进行摘要压缩
└── 支持多轮对话的上下文理解
```
