# AI-Ops 项目概述

## 一句话描述

基于 Go + 本地 LLM 的轻量级 AI Agent 运维平台，通过自然语言对话完成日常运维操作。

## 核心理念

**这是一个 AI Agent 项目，不是传统的运维工具。**

```
传统运维工具：用户选择功能 → 填写参数 → 执行 → 看结果
AI Agent：    用户说需求 → Agent 理解 → 自主决策 → 执行 → 总结反馈
```

## Agent 的本质

```
┌─────────────────────────────────────────────────────────┐
│                    AI Agent 核心循环                     │
│                                                         │
│   感知 (Perception)                                     │
│     │  用户输入、系统状态、历史上下文                      │
│     ▼                                                   │
│   思考 (Reasoning)                                      │
│     │  LLM 理解意图、分析问题、制定计划                   │
│     ▼                                                   │
│   行动 (Action)                                         │
│     │  调用工具、执行命令、获取信息                       │
│     ▼                                                   │
│   观察 (Observation)                                    │
│     │  分析执行结果、判断是否需要继续                     │
│     ▼                                                   │
│   循环或输出                                             │
│       需要更多信息？→ 继续循环                           │
│       任务完成？→ 总结输出给用户                         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 与传统工具的区别

| 维度 | 传统运维工具 | AI Agent 运维 |
|------|-------------|---------------|
| 交互方式 | 菜单/表单 | 自然语言对话 |
| 决策者 | 用户决定每一步 | Agent 自主决策 |
| 灵活性 | 固定流程 | 动态规划 |
| 学习成本 | 需要学习界面操作 | 说人话就行 |
| 复杂任务 | 用户手动串联 | Agent 自动编排 |

## 项目目标

### 短期目标
- 实现基础 Agent 循环
- 支持日志查询、系统检查等常用运维操作
- 提供 Web 界面进行对话和主机管理

### 长期目标
- 可扩展的 Tool 插件系统
- 支持复杂的多步骤运维任务
- 积累运维知识，提升 Agent 能力

## 技术选型

| 组件 | 选择 | 理由 |
|------|------|------|
| 后端语言 | Go | 性能好、并发强、部署简单 |
| LLM | 本地大模型 | 数据安全、无网络依赖 |
| SSH | golang.org/x/crypto/ssh | 标准库、稳定 |
| Web 框架 | Gin | 轻量、性能好 |
| 前端 | Vue3 + ElementPlus | 简单够用 |
| 数据库 | SQLite | 轻量、零配置 |
